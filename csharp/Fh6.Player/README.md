# HEISO Player(再生アプリ)

記録アプリ(`csharp/Fh6.Recorder`)が作ったセッションフォルダ(または配布パッケージ `.heiso.zip`)を開き、動画を再生しながら、同じ瞬間のテレメトリーをグラフにポインターで示す。
タスク 004a(骨組み)・004b(グラフの組み合わせ、スタートへ飛ぶ、接触の表示)・004d(接触の改良、ジャンプ、スリップ・路面・勾配・旋回)・004e(スリップの原因の強調、凡例、ホイールとキーの操作)まで。距離軸のグラフ、コース図、手動補正の画面、コマ送りは 004c で足す。

WPF + WebView2、.NET 10。画面(動画・グラフ・操作)は `wwwroot` の HTML/JavaScript で作っている。

## 動かす

- Visual Studio で `csharp/HEISO.slnx` を開き、`Fh6.Player` をスタートアップにして F5。ビルドすると `HeisoPlayer.exe` ができる
- 「セッションフォルダを開く」で、記録アプリの保存先にある `yyyyMMdd_HHmmss` のフォルダ(後ろにコメントが付いていてもよい。例: `20260927_211710#夏_鳥野山`)を選ぶ。選ぶ画面は毎回、前回開いた記録の 1 つ上(記録アプリの保存先)から始まる(`%LOCALAPPDATA%\HEISO\Player\player.json` に覚える。初めてのときは「ビデオ\FH6Recorder」)
- コマンドラインでも開ける: `HeisoPlayer <セッションフォルダ>`(`session.json` のパスでもよい)。配布パッケージなら `HeisoPlayer <ファイル>.heiso.zip`
- 「パッケージを開く」で、配布パッケージ(`.heiso.zip`)を開く(下の「配布パッケージ」)
- Windows 11 には WebView2 ランタイムが入っている。入っていない環境では起動時に案内が出る

## 画面の見方

- 上: 動画(ブラウザ標準のシークバー付き)。右に操作、コース図、ポインター位置の値、見つけたもの、同期の手動補正、同期の情報(右の欄は動画と同じ高さまで。はみ出したらスクロール)
- 下: グラフ(段の組み合わせは「設定」で変えられる。下記)。横軸は**動画の再生位置**(分:秒)。レースを選んでいれば「横軸」で**距離**にもできる(下記)
- 黄色の縦線が、いま表示しているフレームの位置。フレームの時刻は `requestVideoFrameCallback` で取っている
- メニューやロード中(`is_race_on == 0`)の区間と、変速動作中(`gear == 11`)は線を切っている
- 水色の ▼ がスタート(塗り = レース、線 = 発進)、水色の小さな丸がチェックポイント逃しの復帰、白い ◇ が周のスタート(塗りはゴール)、橙の点線が接触の候補、紫の薄い帯がジャンプ(空中)、紫の短い線が着地
- 赤: 路面の逸脱がスリップやリワインドにつながった場面。路面の段では外れた車輪の帯を赤い枠で、スリップの段ではスリップが限界を下回るまでを薄い赤で示す
- 段の名前の前の色の印が、その段の線の色(凡例)

操作:

| 操作 | 動き |
|---|---|
| Space / 「再生 / 一時停止」 | 再生と一時停止 |
| ホイール(動画かグラフの上) | 1 目盛りで 1 秒前後にシーク(手前に回すと進む)。Shift+ホイールで 1 コマ |
| Ctrl+ホイール(グラフの上) | マウスの位置を中心に横軸を拡大・縮小(その幅が表示幅になる) |

| 横軸(上の欄) | 「時間」/「距離」。距離は 1 つのレースについて。レースが「全体」のまま距離にすると 1 レース目を選ぶ(今の位置がそのレースの外なら、スタートの 3 秒前へ)。距離のままレースを「全体」にすると時間に戻る。ここでの切り替えはその記録の中だけ(開いたときの横軸は設定で決める) |
| レース(上の欄) | 記録の中のレースを選ぶと、そのスタートの 3 秒前へ移り、グラフをそのレースの範囲にする。各レースに開始の位置・コース名・完走か中断かの推定を出す。「全体」か表示幅のボタンで戻る。**レースを選んでいる間は、再生やシークで別のレースに入ると(スタートの 3 秒前から)、選択とグラフ・コース図がそのレースに切り替わる**(レースとレースの間は前のレースのまま) |
| 速さ | 0.25 / 0.5 / 1 倍 |
| 表示幅 | グラフに出す幅(20 秒 / 60 秒 / 全体)。再生中は位置に合わせて送る。横軸が距離のときは、時間軸と同じ拡大率の距離(下の「横軸を距離にする」) |
| グラフをクリック | その位置へ動画をシーク(接触の印の上ならその1秒前へ、ジャンプの帯の上なら飛び出しの1秒前へ、赤い帯の上なら路面の逸脱の1秒前へ) |
| グラフをドラッグ | 拡大(ダブルクリックで戻す) |
| ◀ 前 / 次 ▶ | 今の位置より前 / 後の印へ: スタートの 3 秒前、チェックポイント逃しの復帰の 1 秒前、周のスタート・ゴールの 1 秒前。前に印が無ければ動画の先頭へ。「設定」でレース以外の発進も印にすると、それも対象にする |
| スキップ ON / OFF(上の欄) | 押すたびに切り替える。ON なら再生中、やり直し区間(グラフの灰色の帯)に入ったら、戻った先で走り直す所へ飛ぶ(「◯秒飛ばしました」と出す。一時停止中のシークやコマ送りでは飛ばない)。この記録を開いている間だけで、設定には保存しない。開いたときは設定の「やり直し区間を自動で飛ばす」の状態 |
| 設定(上の欄の右) | 設定のダイアログ(下記) |
| コース図をクリック | その場所を通った時刻へシーク(何度も通っていれば、今の時刻に一番近いもの) |

## 画面の言語(日本語 / 英語)

設定の「画面」タブの「言語」で、自動(Windows の表示言語が日本語なら日本語、それ以外は英語)・日本語・English を選ぶ(2026-09-29。`%LOCALAPPDATA%\HEISO\Player\player.json` の `Language`)。英語のときの名前は「HEISO Solo」。

- 訳は `csharp/Fh6.Core/i18n/strings.json` の 1 ファイルだけ(鍵は日本語の文)。C# は `Fh6.Core` の `Strings.T`、画面は `i18n.js` の `t()` と `data-i18n` の印で引く
- 画面へは、C# がページの読み込みより前に辞書を渡す(WebView2 の、ページの初めに動くスクリプト)。日本語が一瞬出てから英語に変わることは無い
- 言語を変えると、辞書を渡し直して画面を読み直す。記録と再生の位置はそのまま(一時停止する)
- ログのファイルは日本語のまま
- 画面(HTML/JS)の文言は、HTML は `data-i18n`(中身の文)・`data-i18n-title`・`data-i18n-placeholder` の印、JS は `t("…")`。JS の鍵は必ず `"…"` の文字列をそのまま書く(テストが文字列を探して、訳し漏れと使っていない訳を見つけるため)
- 辞書に無い文言は日本語のまま出る。記録に入っているコース名・車名などは訳さない

## 表示の単位(メートル / マイル)

設定の「画面」タブの「単位」で、速度(km/h・mph)、距離(m・km / ft・mi)、標高(m / ft)をそれぞれ選ぶ(2026-09-29)。
「自動」は、Windows の地域が米国か英国ならマイル、それ以外はメートル(地域は C# が `window.HEISO_I18N.region` で渡す。
.NET の `RegionInfo.IsMetric` は英国をメートル法とするので、国の名前で決める)。

- 変わるのは表示だけ。記録のデータとパッケージの形式はメートル法のまま(`units.js` が画面に出すときに直す)
- 速度: グラフの速度の段、読み取り値、接触とジャンプの印の説明、レースの一覧の「終えた瞬間」
- 距離: 距離の横軸(マイルのときは ft・mi の切りのよい所に目盛り)、読み取り値の時刻の横の距離、曲がりの半径、コース図の縮尺の線と範囲のボタン(1 mi / 0.5 mi / 1500 ft / 600 ft)
- 標高: グラフの標高の段、読み取り値、ジャンプの落差
- 旋回の段(1000/R)はメートルのまま(曲がりのきつさの目安で、長さとしては読まないため)

## グラフの設定

「設定」の「グラフの段」で、表示する値を好きな段に入れられる。

| 値 | 中身 |
|---|---|
| 速度 / ギア / アクセル / ブレーキ / 操舵 | テレメトリーそのまま(ギアの 11 = 変速中は線を切る) |
| 旋回 | 車が実際に描いた線の曲がり具合 1000/R(正 = 右)。`angular_velocity_y ÷ speed`。読み取り値に R(m)。**道路の設計の半径ではない**(タイヤの限界で決まる)。18 km/h 未満は出さない |
| 前輪スリップ / 後輪スリップ | `tire_combined_slip` の前2輪・後2輪の平均。1.0 がグリップの限界(点線)。前が大きければアンダー、後ろが大きければオーバー |
| 路面 | 4本の帯(上から左前・右前・左後・右後)。舗装・雪など(0.10)・ダート・ジャンプ台など(0.20)・芝/荒れ地/縁石を色分け(0.10 と 0.20 は雪・ジャンプ台以外の場所にも出る。縁石は 0.24。field-notes セクション 9.6)、縁石(黄)と水たまり(青)は細い線。空中は空白。**タイヤが実際に踏んだ路面**で、コースとしての路面ではない |
| 勾配 | 前後 15m の標高差 ÷ 水平距離(%、正 = 上り)。座標から求める(車体の pitch はサスペンションの沈みを含むので使わない) |
| 標高 | `position_y`(m)。段の上下は、コース(レースを選んでいればそのレース、全体なら記録の走行中)の最低〜最高に 5% の余白を付けて固定する(スクロールしても変わらない)。標高差が 50m 未満のコース(都内など)は、真ん中を中心に 50m の幅にする(小さな凹凸を大げさに見せない) |
| 接触の印 / ジャンプ | 印(下記) |

コースとしての路面の変化や道路の R は、複数の走行から作るコースDB(spec の将来段階)ができたら重ねる。

- 札の × で外す、「+ 追加」で使っていない値を入れる、札をドラッグして別の段へ移す
- 段ごとに高さ(小・中・大)、▲▼ で並べ替え、削除、「+ 段を追加」
- 段の中で1つ目の単位は左、2つ目は右に目盛りを付ける。3つ目以降の単位は目盛りを出さずに段の高さに合わせて描く
- 変更はすぐ反映され、次回も使う(アプリの中に保存)。「自分の設定として保存」でプリセットの一覧に「自分の設定」が増える

## スタート・接触・ジャンプの判定(Fh6.Core)

開くたびにテレメトリーから計算する(保存はしない)。閾値は暫定で、実データを見て調整する。
時刻の差は受信時刻(`recv_time`)で測る。`timestamp_ms` は 60fps 近くでは約 32ms 刻みで、約半分の行が直前と同じ値になるため。

- **スタート**(`StartDetector`): 1 km/h 未満が 1 秒以上続いた後に 5 km/h を超えた瞬間。停止区間(メニュー・ロード・カウントダウン)の明けに止まった状態から始まった場合は、止まっていた時間が短くてもスタートとする(FH6 のレースはカウントダウン中が停止区間で、グリーンフラッグの瞬間に速度 0 で始まるため)。その時点で `race_pos >= 1` ならレース、それ以外は発進
- **接触の候補**(`ContactDetector`): 水平方向の加速度 √(ax² + az²) が 40 m/s²(約 4G)を超え、前のサンプルから 25 m/s² 以上増えた瞬間。ブレーキの有無は問わない(ブレーキ中の追突、横から押されて速度が上がる接触も拾う)。0.5 秒以内は1件に。前後とも 5 km/h 未満(チェックポイント逃しの復帰直後の揺り戻し)は除く。直前 0.3 秒以内に空中だったものは「着地」として分ける。**軽く当てられた接触は加速度にほとんど表れず、拾えないことがある**
- **スタートの種類**: レース / 発進 / 復帰。レース中に停止区間を挟まず位置が 1 サンプルに 20m 超飛び、そこで止まってから動き出したものは、チェックポイント逃しの「復帰」
- **路面の逸脱とスリップ**(`SurfaceExcursionDetector`): 4 輪とも舗装が 0.3 秒以上続いた後、どれかの車輪が舗装から外れた状態が 0.1 秒以上続いた瞬間(0.1 秒未満のちらつきは無視、縁石(0.24)は外れたとみなさない、30 km/h 以上、空中を除く)。その 0.3 秒前から 2 秒後までにスリップ(前後平均の大きい方)が 1.0 を超えたか、2 秒以内に停止区間に入ったものだけを強調する
- **周**(`LapDetector`): `lap_no` が増えたら周のスタート(前の周のタイムは直前の `cur_lap`)。増えてから 2 秒以内にレースが終わったらゴール(ゴール直後に周回数が 1 増える断片のため)。レース中に `lap_no` が一度も増えない場合(タイムアタックなど)は、スタート地点から 300m 以上離れた後、20m 以内・向き 30 度以内で戻ってきた瞬間を周のスタートとし、周のタイムはスタート地点の通過の間隔(`dist_traveled` が 0 より大きい間だけ)
- **ジャンプ**(`AirDetector`): 4輪とも `norm_suspension_travel` < 0.03 が 0.15 秒以上続いた区間。空中の時間、飛び出しの速度、最高点から着地までの落差

## レースの一覧(Fh6.Core の RaceSegmentDetector)

記録アプリと同じ判定(`RaceTracker`)で、記録済みの CSV からレース区間を作る。

- レースの開始: `race_pos` が 0 → 1 以上か、停止区間の明けに `race_pos` が 1 以上のまま `cur_race_time` が 0.5 秒未満に戻った(リスタート・続けて次のレース)。リワインドは 0 より大きい値に戻るので含めない
- 区間の終わり: `race_pos` が 0 に戻るか、次のレースが始まるか、記録の終わりまで
- 完走か中断かは**推定**(2026-09-28 に見直し、2026-09-30 に 1 と 2 の順を入れ替え。何で決めたかを、レースの選択肢にマウスを重ねると出す)。次の順で決める
  1. 直後の停止区間の明けに順位 0 で、レースの時計が停止区間の半分以上進んでいた → 完走(リザルト画面の間は時計が進む)。半分未満なら中断(ポーズメニューの間は時計がほぼ止まる。開くまでに 1 秒ほど進むことがある)
  2. 終わる直前(2 秒以内)に周回数が増えた → 完走(ゴールで周回数が増える種類のレース)。周回レースで次の周に入った直後にメニューからやめても周回数が増えた直後に終わるので、1 より後に見る(091446)
  3. 停止区間のまま記録が終わった → 完走(リザルト画面で録画を止めた)
  4. それ以外(すぐ次のレースが始まった): 終えた瞬間の速度が 150 km/h 以上で、直後の停止区間が 12 秒以上なら完走
- ゴール直後に 0.5 秒未満だけ出るレース中の行(周回数が 1 増えるだけの断片)は、終えた瞬間の判断から外す。この行の時計はリザルト画面の分だけ進んでいるので、レースタイムはその手前のゴールの行で取る
- コース名と車名: `session.json` の出来事から取る(`race_start` → `course_confirmed` → 記録アプリで後から直した `race_edited` の順に、後のものほど優先。車名はレース開始の時点で検知していた車両に、レースの後でも次に車両が変わるまでの確定を重ねる)。無ければ「コース不明」で、車名は出さない
- タイムアタックのように `race_pos` が 0 のままのイベントは、レースの一覧には入らない(スタートの印と周の印は出る)

## レースに名前を付ける

上の欄でレースを選び、「名前を付ける」を押すと、そのレースのコース名・車名・セッティング名を付けられる(記録アプリの「直前のレース」の直し方と同じ中身)。

- コース: 登録済みのコースから選ぶ(スタートの位置で一致したものを先頭に「スタートの位置が一致」と出し、選んでおく)か、「新しく登録」でレース名と種類を入れる。登録済みのコースの名前を書き換えると、登録している名前そのものが変わる
- 車: 車名(その車種の登録名を最初から入れておく)と、セッティング(同じ組の登録済みのものか、「新しく登録」か、「付けない」)
- 候補は記録の保存先(セッションフォルダの 1 つ上)の登録ファイル `fh6_registry.json` から読む(読むだけ)
- 保存すると:
  1. その記録の `session.json` に `race_edited`(`source: player`)を足す。レースの一覧と書き出すパッケージに、すぐその名前が出る
  2. 保存先の登録の受け渡し用のファイル `fh6_registry_inbox.json` に頼みを足す。記録アプリが、次に起動したとき(起動中なら数秒で)登録ファイルに取り込む。登録ファイルを直接書き換えないのは、記録アプリが起動中に読み書きしているため
- パッケージを開いているときと、記録中の記録には保存できない

## 横軸を距離にする(Fh6.Core の RaceDistance)

レースを選んで「横軸」を「距離」にすると、スタートからの距離(m。座標の水平距離の積み上げ)でグラフを並べる。

- リワインドとチェックポイント逃しの復帰は、それまでに走った道筋の近く(30m 以内)に戻っていれば、そこの距離から数え直す。
  戻った先より後に走っていた「やり直した走り」はグラフに出さず、最後まで残った走りだけを並べる(その中の印も出さない)
  - 戻った先は、直前の道筋から順にさかのぼって最初に近づいた所(一番新しい通過)。ただしほぼ道筋の上(5m 以内)の所が 500m 以内にあればそちら(ヘアピンの反対側の道を選ばないように)。周回で前の周の同じ場所には戻らない
  - 道筋から離れた所への復帰は、距離を足さずに続ける
- `dist_traveled` は使わない(メートルではなく、コースごとに係数が違うため)
- ポインターは今の動画位置の行の距離(やり直した走りの中でも、その時点の距離)。クリックはその距離を通った時刻へ
- 表示幅のボタンも使える(2026-09-28)。幅は、時間軸と同じ拡大率の距離: レースの全長 ×(表示幅の秒 ÷ レースの長さの秒)。速度によらず一定で、例えば 246.5 秒・7,840m のレース(001930)なら 20 秒 = 636m、60 秒 = 1,908m、「全体」= レース全体
  - 再生中は、ポインターが右の 8 割を越えたら幅を保ったまま送る。ボタンを押してもレースの選択は外さない
  - Ctrl+ホイールで拡大・縮小した幅も、同じ比で秒に直して表示幅として覚える(時間軸に戻しても同じ拡大率)
  - 距離の無い位置(リワインドの画面などの停止区間)では、明けて走りに戻った所の距離を基準に幅を置く
- 同じコースの記録どうしで、レースの距離はほぼ揃う(フェスティバルスプリント 7,850 / 7,857 / 7,857m、東京鉄道 6,848 / 6,827m など)

## 飛ばせる区間(クリーン再生)

上の欄の「スキップ ON」で、再生中に次の 2 種類を飛ばす。グラフでは全段に灰色の薄い帯で出し、「見つけたもの」に種類ごとの件数と合計の長さを出す。

**やり直し区間**: レースの中で、リワインドやチェックポイント逃しの復帰で捨てた走りの始まりから、戻った先で走り直す所まで(`Fh6.Core` の `RaceDistance.RedoRanges`。距離軸で出さない「やり直した走り」と同じ判定)。
間のリワインドの画面(停止区間)も含む。

- 0.3 秒より短いものは除く。間が 0.5 秒より短い区間はまとめる(走り直してすぐまたリワインドした所)
- 110104(リワインド 30 回以上)では 15 件・合計約 3 分
- レースの外(フリーローム)と、レースの一覧に入らないイベント(タイムアタック)は対象外

**一時停止(フォトモード・ポーズメニュー)**: レース中の停止区間のうち、明けたときにレースの経過時間がほぼ止まっていて(0.5 秒未満しか進まない)、位置もほとんど動いていない(5m 未満)、2 秒以上のもの(`Fh6.Core` の `RacePauses`)。

- フォトモードとポーズメニューはテレメトリーでは同じ形で、区別できない(どちらも飛ばす)
- フォトモード中は車の速度が入る前の値のまま止まっている(173311 では 31 km/h)ので、速度では「静止」と判定できない。レースフラグ(`is_race_on`)と経過時間で見分ける
- 路上でスピンして止まっている間は、`is_race_on` が 1 のままで経過時間も進むので対象外(走りの一部として残す)
- ゴール後のリザルト画面は経過時間が進み続けるので対象外。リワインドは経過時間が巻き戻るので、やり直し区間の方で扱う
- 173311: スタート直後のフォトモード 34.7 秒。000503: レース中のメニュー 3.4 秒

計算は `Fh6.Core` の `RaceSkips`(配布パッケージの `package.json` の `skips` と同じ結果)。

## 配布パッケージ(書き出す・開く)

レース 1 本を、動画・テレメトリー・情報の 1 つのファイル(`.heiso.zip`)にまとめて人に渡す(タスク 005。形式は `docs/session-format.md`「配布パッケージ」)。

**書き出す**: 上の「レース」でレースを選び、右上の「書き出す」。書き出し方を選んで(前回選んだ方を選んでおく)、保存先を選ぶ。

- 名前の既定値は `<フォルダ名>_<コース>_<車>.heiso.zip`(720p なら `_720p` を付ける)。最初の場所は前回書き出したフォルダ(初めてなら記録アプリの保存先)
- 動画はレースの 5 秒前からゴールの 5 秒後まで。リザルト画面のランキング(名前が出る)は入らない
- **元の画質のまま**: 作り直さずに切り出す(頭は、その前で一番近いキーフレーム)。画質はそのままで一瞬で終わる(4 分のレースで約 200MB、約 2 秒)
- **720p に縮める**(2026-09-28): ffmpeg で作り直す(`Fh6.Core` の `Ffmpeg`)。頭はレース開始のちょうど 5 秒前のコマ。H.264・キーフレーム 1 秒・平均 4 Mbps(30fps)/ 6 Mbps(60fps)・AAC 128 kbps。4 分のレースで NVENC なら約 16 秒・約 140MB
  - 作っている間は画面の下に進み具合を出し、「中止」で止める(途中のファイルは残さない)
  - ffmpeg は同梱しない。探す順: 設定の「書き出し」の場所(ファイルかフォルダ。フォルダなら中の `bin` や、展開した版のフォルダの `bin` も見る)→ PATH → 再生アプリのフォルダの中・隣(HEISO を展開したフォルダ)の `ffmpeg` フォルダ → `%LOCALAPPDATA%\HEISO\ffmpeg`
  - エンコーダは、その PC で小さな動画を実際に作って確かめ、使えるものを NVIDIA(`h264_nvenc`)→ AMD(`h264_amf`)→ Intel(`h264_qsv`)→ CPU(`libx264`)の順に選ぶ(設定の「書き出し」で選ぶこともできる)。確かめた結果は、設定を変えるまで覚えておく
  - ffmpeg が見つからないか、使えるエンコーダが無ければ、「720p に縮める」は選べない(理由を出す)
- テレメトリーは同じ範囲の行。受信時刻(`recv_time`)は元のまま
- 手動補正は引き継ぐ。利用者の PC のパス(録画の保存先)は入れない
- 記録中の記録、録画の無い記録、録画開始の時刻の無い古い記録(`HeisoRecorder --resync` で作り直せる)からは書き出せない。パッケージから、もう一度パッケージは作れない

**開く**: 「パッケージを開く」で `.heiso.zip` を選ぶ(またはコマンドラインで渡す)。

- `%LOCALAPPDATA%\HEISO\Player\packages\<名前>_<ハッシュ>` に展開して、普通の記録と同じに開く。同じファイルは展開し直さない。展開したものは新しい 5 つだけ残す
- レースは `package.json` の範囲・コース名・車名を使う(切り出したテレメトリーでレースの判定をやり直さない)
- 手動補正は展開した先に保存する(元の `.heiso.zip` は変えない)
- 新しい版のアプリで作った(形式の番号が大きい)パッケージは開かない

## コース図

コース図の下のボタンで、2D(真上から)と 3D(立体)、色のモード(今の周 / 路面の色)を切り替える。選んだものは覚えて次の記録にも使う。

### 3D

- 走行軌跡を幅のある帯(道)として、標高(`position_y`)を高さに描く(`wwwroot/courseview3d.js`。WebGL2 を直接使い、外部の部品は使わない)
- 座標は左手系なので、右手系の行列に渡すときに南北の向きを反転している(反転しないと左右が逆に見える)
- 視点: 真上(北が上)/ 斜め / 後ろから(車の後ろ上方から。進む向きに合わせて回る)。左ドラッグで回転、右ドラッグで平行移動、ホイールで拡大・縮小、ダブルクリックで選んだ視点に戻す
- 範囲のボタン(全体 / 2km / 1km / 500m / 200m)は 2D と同じ。全体以外は今の位置を真ん中にして追従する(回転・拡大しても追従は続き、平行移動すると止まる)
- 高さの強調: 自動(標高差がコースの広さの 8% くらいに見えるように 1〜8 倍)/ ×1 / ×3 / ×5。標高差はコースの広さに比べて小さい(11〜319m に対して 1〜3km)ので、強調しないと平らに見える
- 道の帯の幅は画面で約 6px(近づいたら 8m より細くしない)。色は 2D と同じ(やり直し区間は赤の半透明で細く、今の周・グラフの範囲は少し上に重ねる)
- クリックでその場所を通った時刻へ(何度も通っていれば今の時刻に一番近いもの。やり直し区間は除く)
- WebGL2 が使えない PC では 2D のままにして知らせる

### 区切って追従する(「区切り」)

範囲を 2km / 1km / 500m / 200m にしているとき、いつも今の位置に合わせて動かすのではなく、コースを区間に分けて、区間の中では視点(中心と向き)を動かさない。
車が次の区間に入ったら、0.4 秒かけて次の区間の視点へ移る。2D・3D の両方で使える。

- 区切る所は直線の真ん中: 曲がりが緩く(1000/R の絶対値が 3 未満 = 半径 330m より大きい)、50 km/h 以上で 1 秒以上続く所。コーナーの途中やスピン中(曲がりが急で遅い)は区切りにならない
- 1 つの区間は、選んだ範囲の 8 割の四角に収まる長さ。収まる直線が無いときは、その中の後ろ半分で一番曲がりの緩い所で区切る。位置の飛び(チェックポイント逃しの復帰・リワインド)でも区切る
- 3D の「後ろから」では、区間の向き(始まりから終わりへ)に固定する。スピンしても視点は回らない(211710 のスピンで、いつも追従だと視点の向きが 47° → 239° と回ったのが、区切りでは 47° のまま)
- 211710(1 周 約 1.1km)では、200m で 24 区間、500m ではコース全体が 1 つの四角に収まるので 2 区間(復帰の所だけで移る)

### 路面の色

- 4 輪の路面が同じ行はその路面の色(グラフの路面の段と同じ分け方)、違う行は「混在」(紫)。空中の間は直前の色を続け、3 行未満のちらつきはならす
- 実データでは 88〜100% の行が 4 輪同じ。混在は 5〜12% で、縁石に乗った・芝に片側だけ落ちた・路面の変わり目などの場面
- 2D では、ほかの周を薄く、今いる周をはっきり、グラフの範囲を白い細い線で重ねる。3D では、グラフの範囲を帯の真ん中の白い細い線で出す
- 色の凡例をコース図の下に出す

### 2D

真上から見た走行軌跡(北が上)。x = 東を右、z = 北を上に描く(FH6 の座標は左手系なので、この向きで左右は正しい)。

- レースを選んでいればそのレースの行、選んでいなければ記録全体の走行中の行。50m を超える飛び(ファストトラベル・復帰)で線を切る
- 色: 本命の走りは灰色、そのうち今いる周(周の無いレースはレース全体)を青、その中でグラフに出している範囲をさらに明るく。周回コースで何周も重なる線のうち、今の周だけが分かる。やり直し区間(リワインド・チェックポイント逃しで捨てた走り)は暗い赤の点線で、本命の走りから枝分かれして見える
- 今の位置は黄色の矢印(進む向き)
- 下のボタンで範囲を切り替える: 全体 / 2km / 1km / 500m / 200m(一辺の長さ)。全体以外は今の位置を真ん中にして追従する(北が上のまま)。左下に縮尺。選んだ範囲は覚えて次の記録にも使う
  - 目安(200 km/h のとき): 2km = 前後約 18 秒の流れ、1km = 前後約 9 秒、500m = ブレーキからコーナーの続き、200m = 1 つのコーナーのライン

## 同期の手動補正

映像とグラフが少しずれているときに、映像で分かる瞬間で合わせる。

1. 着地の衝撃やスタートの瞬間などのコマで止め(コマ送りを使うとよい)、「このコマを使う」
2. 「グラフで指す」を押してから、グラフで同じ瞬間をクリックする(接触・着地・周の印の近くなら、その印の時刻に合わせる)
3. ずれ(秒とコマ数)を確かめ、メモを付けて「保存」

保存すると `session.json` の `video.manual_sync` に点が足され、グラフと印がその分ずれる(開き直しても残る)。
「補正を消す」で、この記録の手動補正を全部消して自動の同期に戻す。記録中の記録には保存できない。

## 同期の情報(確認用)

同期が正しいかを確かめるための表示(動画0秒の決め方はタスク 003 で確定)。

| 項目 | 意味 |
|---|---|
| 同期の方式 | 「録画開始イベント」= OBS の録画開始イベントを受けた時刻を動画0秒とする(既定。2026-09-28 確定)。「録画中の対応表」= `video.sync_samples` の補間(比較用。OBS の報告が約1秒遅れるので、約1秒ずれる) |
| 対応表の点 | 変換に使った点の数(往復 150ms 超などで使えない点は除く)。選んだ方式の基準が無く別の基準で代用したときは赤で出す |
| 終端の検算 | `video.end_check_sec`。±0.1 秒を超えると赤 |
| 時計の比 | `video.clock_rate` |
| 手動補正 | `video.manual_sync` の点の数と、ずらしている量 |

時刻の変換はすべて `Fh6.Core` の `VideoTimeMap` で行い、JS には横軸を動画の秒に直した系列を渡している。

## 落ちたときの調べ方

- **ログ**: `%LOCALAPPDATA%\HEISO\Player\logs\player-yyyyMMdd.log`(7 日分)。ほかのプロセスがファイルを開いていても書けるよう、読み書き・削除を許す開き方で追記する。それでも書けなければ `player-yyyyMMdd-<プロセス番号>.log` に書き、理由を `write-error-<プロセス番号>.txt` に残す。起動(アプリ・.NET・Windows・WebView2 の版)、開いた記録(行数・レース数・動画・読み込み時間)、画面とのやりとり、主な操作(レース・横軸・スキップ)、例外を 1 行ずつ書く
  - C# の拾われなかった例外(画面の処理・非同期・それ以外のスレッド)、JS のエラー(`window.onerror`・拾われなかった Promise)、WebView2 の中のプロセスが落ちたこと(`ProcessFailed`)も書く
  - 画面の処理の例外は、記録して止めずに続ける(画面に「予期しないエラーが起きました」と出す)
- **画面の立て直し**: WebView2 の描画のプロセスか GPU のプロセスが落ちた・止まったときは、画面を読み直して、同じ記録・同じ位置(約 2 秒ごとに覚えている動画の位置)に戻す。再生中だったら再生を続ける。WebView2 全体が止まったときは、起動し直すよう知らせる
  - GPU のプロセスは WebView2 が作り直すが、動画の映像だけが止まって音は鳴り続けることがあった(2026-09-28。GPU のプロセスが、動画を画面に重ねる処理 `SwapChainPresenter::SetupPresentToSwapChain` で固まり、見張り役 `GpuWatchdogThread` に作り直された)
- **ビデオオーバーレイを使わない**: 上の固まり方を避けるため、WebView2 に `--disable-direct-composition-video-overlays` を渡して、動画を DirectComposition のビデオオーバーレイで表示しない(GPU の負荷は少し増える)。`player.json` の `VideoOverlays` を `true` にすると使う(画面の設定には出していない)
  - 開発で環境変数 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` を付けて起動すると、アプリの起動オプションが置き換わる。確認で付けるときは、`--autoplay-policy=no-user-gesture-required --disable-direct-composition-video-overlays` も一緒に付ける
- **前回の異常終了の知らせ**: 起動中は `logs\running-<プロセス番号>.flag`(プロセスの起動時刻入り)を置き、正常に終わると消す。起動したときに、もう動いていないプロセスの印が残っていれば、画面の上に「前回は正常に終了しませんでした」と、ログとクラッシュダンプの場所を出す(「ログのフォルダを開く」「閉じる」)。印は起動ごとに別なので、2 つ同時に開いても、動いているもう 1 つを異常終了とは見ない
- **クラッシュダンプ**: Windows のエラー報告が `%LOCALAPPDATA%\CrashDumps\HeisoPlayer.exe.<番号>.dmp` に残す(ローカルダンプが有効な PC だけ。この開発 PC では有効)。Windows SDK のデバッガーで、落ちた所の呼び出しの流れを読める

```
"C:\Program Files (x86)\Windows Kits\10\Debuggers\x64\cdb.exe" -z <ダンプ> -c ".ecxr; kn 40; q"
```

## 作りの注意

- セッションフォルダは仮想ホスト `https://session.heiso/`(フォルダの外にある動画は `https://video.heiso/`)に割り当てて `<video>` で読む。
  割り当ては読み込み済みのページには効かない(動画が「対応していない形式」のエラーになる)ので、セッションを開くたびにページを読み直している
- WebView2 のキャッシュは `%LOCALAPPDATA%\HEISO\Player\WebView2` に置く
- **WebView2 のイベント(`WebMessageReceived` など)の処理の中で、閉じるまで待つ画面(`ShowDialog`・`MessageBox`)を開かない。** 開いている間に WebView2 あての処理が届くと、WebView2 が割り込みを検出して止まり、アプリごと落ちる(`EmbeddedBrowserWebView.dll`、例外 `0x80000003`。2026-09-27〜28 に 8 回)。`Dispatcher.InvokeAsync` でイベントの処理を終えてから開く
- `session.json` に書き込むのは手動補正の保存と消去だけ(書く直前に読み直し、知らないキーは残す)
