# HEISO Recorder(HEISO の記録アプリ)

FH6 のテレメトリ記録と OBS 録画を、ブラウザ(PC・スマホ)から同時に開始・停止するアプリ。
.NET 10 / ASP.NET Core。NuGet パッケージは使っていない。
パケット定義・記録ファイルの書き出し・同期計算は `csharp/Fh6.Core`(UI に依存しないライブラリ)にある。

## 準備

1. **OBS**: 「ツール → WebSocketサーバー設定」で「WebSocketサーバーを有効にする」をオン。
   認証を使うならパスワードを `appsettings.Local.json` に書く(ポートは既定 4455)。
   このファイルは Git に入らない。書式は `appsettings.Local.example.json` を参照
2. **FH6**: 設定 → 画面表示とゲームプレイ → テレメトリ の「データ出力」をオン、IP `127.0.0.1`、ポートは `appsettings.json` の `UdpPort`(既定 5400。5200〜5300 はゲームが使うので避ける)と同じにする。
   同じポートを使うほかのテレメトリーのアプリとは同時に使えないので、どちらか一方だけ動かす。
   SimHub などほかのアプリと併用するなら、`ForwardTo` でそのアプリへ送り直す(下の「UDP の送り直し」)。
3. Visual Studio で `csharp/HEISO.slnx` を開き、`Fh6.Recorder` をスタートアップにして F5(またはこのフォルダで `dotnet run`)。
   ビルドすると `HeisoRecorder.exe` ができる。

起動すると PC のブラウザが開き、スマホ用の QR コードが出る。初回は Windows ファイアウォールの確認が出るので「プライベートネットワーク」を許可する。
URL の `k=...` は合言葉で、保存先フォルダの `.access_key` に保存され、次回以降も同じ(ブックマーク可)。
終了は Ctrl+C。記録中なら録画を止めてファイルを閉じてから終わる(ウィンドウの×は保存が間に合わないことがある)。

## UDP の送り直し(パススルー)

ゲームの Data Out は 1 か所にしか送れないので、SimHub などほかのテレメトリーのアプリと併用するときは、受けた UDP をそのまま送り直す(2026-09-28)。

- `appsettings.Local.json` の `Recorder.ForwardTo` に、送り先を `"127.0.0.1:5301"` のように並べる(複数可)。空なら送らない
- 受けたバイト列を、読み取りより先に、大きさによらずそのまま送る。記録していないときも送る
- 送り先のアプリが動いていなくても記録は止めない(送れなかった数を数えて画面に出す)
- 自分の受信ポートを同じ PC へ送る設定(ぐるぐる回る)と、読めない書式は使わず、理由を画面のテレメトリーの欄に赤で出す
- 画面のテレメトリーの欄に「転送 127.0.0.1:5301」、マウスを重ねると送った数

## 画面の言語と速度の単位

画面(ブラウザ)・コンソールの表示・エラーと知らせは、日本語と英語で出す(2026-09-29)。`appsettings.json`(か `appsettings.Local.json`)の `Recorder` で決める。

- `Language`: `auto`(初期値。Windows の表示言語が日本語なら日本語、それ以外は英語)/ `ja` / `en`。ログは日本語のまま
- `SpeedUnit`: `auto`(初期値。Windows の地域が米国か英国なら mph、それ以外は km/h)/ `kmh` / `mph`。画面の速度と「最近のできごと」のレース終了の速度に使う
- 訳は `Fh6.Core/i18n/strings.json` の 1 ファイルだけ。画面へは `/i18n-data.js`(辞書)と `/i18n.js`(`t()`・`data-i18n`。Fh6.Core から出す)で渡す
- `session.json` の `events` の説明(`detail`)は日本語のまま書く(記録データは訳さない)。画面の「最近のできごと」には、今の言語の文を別に作って出す。
  ただし OBS や受信のエラーの文(`video.error` など)は、画面の言語で書かれる
- 英語のとき `--setup-obs-profiles` は、プロファイルを英語の名前(「HEISO Minimum / Light / Medium / Standard / High」)で作る。
  日本語・英語どちらの名前のプロファイルがあっても、それを使う(作り直さない)

## 使い方

- 丸ボタンで記録開始。記録中はもう一度タップで構え、3秒以内にもう一度タップで停止(誤タップ防止)
- 画面のふちが赤 = 録画+ログ、青 = ログのみ(OBS 未接続時や「OBSで録画する」オフ時)
- 「マーカーを打つ」で `session.json` の `markers` に時刻を記録(ミニイベントの区切りなどに)
- テレメトリは記録していないときも受信していて、状態・速度・車を画面に出す
- 車両・コースの確認カード(下記)は、記録していないときも出る。登録した内容は保存先の `fh6_registry.json` に残り、次から名前で出る

## 録画するシーン

「録画の画質」の下の「録画するシーン」で、OBS のどのシーンを録画するかを選べる(2026-10-05)。
画面キャプチャ用などに OBS で別のシーンを選んだまま戻し忘れると、そのシーン(ゲームが映っていない)が録画されてしまうため。

- 初めは「OBS で今選んでいるシーン」(切り替えない)。選択肢に「今: ○○」と今のシーンを出す
- シーンを選ぶと、録画の前に OBS のプログラムのシーンをそれに切り替え(`SetCurrentProgramScene`)、録画が終わったら元のシーンに戻す。シーンの中身(ソース)は変えない
- 選んだシーンは保存先フォルダの `.recorder_prefs.json` に覚え、次の起動でも使う(画質と同じファイル)
- 選んだシーンが OBS に無いときは、切り替えずに今のシーンで録画し、理由を画面に出す
- 元のシーン名は `.recorder_obs_scene_restore.json` にも書き、アプリが途中で落ちたときは次に OBS へつながった時点で戻す
- 録画したシーンは `session.json` の `video.scene`(`docs/session-format.md`)

## 録画の画質

「OBSで録画する」の下の「録画の画質」で、録画のデータ量を段階で選べる。段階ごとに OBS のプロファイル「HEISO ○○」を用意しておき、
録画の間だけそのプロファイルに切り替え、終わったら元のプロファイルに戻す。
最後に選んだ段階は保存先フォルダの `.recorder_prefs.json` に覚え、次の起動でも使う。初めは「OBS の設定のまま」(何も変えない)。

### 最初に1回: プロファイルを用意する

**OBS を閉じてから**、次を実行する(ビルドした `HeisoRecorder.exe` のフォルダで)。

```
HeisoRecorder --setup-obs-profiles
```

- 今使っている OBS のプロファイル(`%APPDATA%\obs-studio\user.ini` の `ProfileDir`)のフォルダを丸ごとコピーして、下の5つを作る。元にするプロファイルは `--from <フォルダ名>` で指定もできる
- コピーの `basic.ini` のうち、出力解像度・fps・録画画質(と「配信と同じ」の段階ではビットレート・配信用エンコーダ)を書き換える。録画先・形式・音声・エンコーダなど、それ以外は元と同じ
- そのうえで出力モードを「詳細」にし、**録画のキーフレーム間隔を 1 秒**にする(下の「キーフレーム間隔」)
- 元のプロファイルには触れない。OBS が起動中なら何もしない(OBS が終了時に上書きするため)
- すでにある「HEISO ○○」は、出力モードが「基本」のもの(前の版で作ったもの)だけ「詳細」に直す。そのプロファイルの今の値(利用者が直したビットレートなど)を引き継ぐ。元のファイルは `basic.ini.simple.bak` として残す。「詳細」のものには触れない
- 元のプロファイルの出力モードが「基本」でないと作らない
- OBS を起動するとプロファイルのメニューに並ぶ。中身は OBS の設定画面で自由に直してよい(記録アプリは名前で切り替えるだけ)

| 段階 | プロファイル | 出力解像度 / fps | 録画画質 | 目安の容量 |
|---|---|---|---|---|
| 最小 | HEISO 最小 | 540p / 30 | 配信と同じ、2,500 kbps | 約 19 MB/分 |
| 軽量 | HEISO 軽量 | 720p / 30 | 配信と同じ、6,000 kbps | 約 45 MB/分 |
| 中間 | HEISO 中間 | 1080p / 30 | 配信と同じ、10,000 kbps | 約 75 MB/分 |
| 標準 | HEISO 標準 | 1080p / 30 | 高画質・ファイルサイズ中 | 約 125 MB/分 |
| 高画質 | HEISO 高画質 | 1080p / 60 | 区別のつかない画質 | 約 250 MB/分 |
| OBS の設定のまま | (切り替えない) | — | — | — |

- 出力解像度の幅は、基本(キャンバス)解像度の縦横比から決める(16:9 なら 960 / 1280 / 1920)
- 「配信と同じ」の段階は、配信用のエンコーダを録画用と同じもの(NVENC など)にしている。x264(CPU)だとゲーム中に重いため
- 高画質(60fps)は、モニターとゲームが 60fps で動いていないと意味がない
- 目安の容量は理論値。前回の記録の欄に実際の容量(MB/分)が出るので、それを見て直す

#### キーフレーム間隔

配布用に動画を切り出すと、切り出しの頭はキーフレームにしか置けない(作り直さずに切るため)。
OBS の「基本」モードではキーフレーム間隔を決められず、エンコーダ任せになる(NVENC では 250 コマ = 30fps で約 8.3 秒。2026-09-28 に実際の録画で確認)。
そこで HEISO のプロファイルは「詳細」モードにして、録画用エンコーダの `keyint_sec` を 1 にする。

「詳細」モードの録画設定は、「基本」モードの値から OBS の「基本」モードと同じ中身になるように作る(OBS の `SimpleOutput.cpp` に合わせた)。

| 「基本」の値 | 「詳細」の値 |
|---|---|
| 出力モード | `[Output] Mode=Advanced`。録画は `RecType=Standard`、拡大縮小なし(`RecRescaleFilter=0`)、分割なし |
| 録画先・形式 | `SimpleOutput` の `FilePath`・`RecFormat2` → `AdvOut` の `RecFilePath`・`RecFormat2` |
| エンコーダ | 「配信と同じ」は `StreamEncoder`、それ以外は `RecEncoder` を ID に直して `AdvOut.RecEncoder`(`nvenc` → `obs_nvenc_h264_tex`、`x264` → `obs_x264`、QSV・AMD・HEVC・AV1 も。OBS 31 以降の ID)。知らないエンコーダならその段階は作らない |
| 画質 | `recordEncoder.json`。「配信と同じ」は CBR で `VBitrate`。標準は CQP 23、高画質は CQP 16(x264 は CRF。対角 2000px 未満の解像度では OBS と同じく値を下げる)。NVENC のプリセット(`NVENCPreset2`、例 `p5`)を引き継ぐ |
| 音声 | AAC(`ffmpeg_aac`)。「配信と同じ」は `ABitrate`、それ以外は 192 kbps(OBS の「基本」と同じ)。トラックは `RecTracks` |

- `SimpleOutput` の値は消さずに残す(OBS の設定画面で「基本」に戻せば元どおり。記録アプリは `session.json` の `rec_quality`・`bitrate_kbps` をここから読む)
- OBS の設定画面で「詳細」の値を直してよい。そのときは `session.json` の `rec_quality`・`bitrate_kbps` は実際と合わなくなる

### 録画のときの動き

- 選んだ段階のプロファイルが OBS に無ければ、画面の選択肢に「OBS に未作成」と出る。そのまま記録すると、今の OBS の設定で録画する
- 切り替えられなかったときは今の設定のまま録画し、理由を画面と `session.json` の `events` に出す
- 元のプロファイル名は保存先フォルダの `.recorder_obs_restore.json` にも書く。アプリが途中で落ちたときは、次に起動して OBS へつながった時点で戻す
- 使う obs-websocket の要求: `GetProfileList`、`SetCurrentProfile`(切り替え)、`GetVideoSettings`・`GetProfileParameter`(切り替えた後の実際の値(出力解像度・fps・出力モード・録画画質)を `session.json` に残すための読み取りだけ)
- **OBS の設定値を外から書き換えない**。外から解像度などを変えると OBS が録画用のエンコーダを作り直さず、録画が始まらなくなった(2026-09-27、OBS 32.2.2 で確認。ログに `encoder 'simple_aac_recording' has no media set`)。プロファイルの切り替えなら OBS 自身が作り直す

## 車両とコースの確認

受信している間はずっと、車両の切り替わりとレースの開始・終了を見ている(判定は `Fh6.Core` の `RaceTracker`)。

- **車両の確認カード**: 記録の開始時と、車種・クラス・PI・駆動方式・気筒数のどれかが約 1 秒(30 パケット)続けて変わったときに出る
  - 未登録の車なら車名を入れる。同じ車で仕様が違えば、セッティング名を入れて「新しいセッティングとして登録」
  - 登録済みの組み合わせなら、前回のセッティングを選んだ状態で出るので「この内容で確定」を押すだけ
  - 記録していない間に確定しておけば、記録の開始時にはカードを出さない
  - PI が変わらないセッティングの変更(ギア比など)はテレメトリーから分からないので、「セッティングを変えた(PI は同じ)」で名前を付ける
- **コースの確認カード**: 登録していないコースでレースが始まると出る。レース名と種類(ロード・ダート・クロスカントリー・ストリート・ドラッグ・その他)を入れるか、登録済みのコースを選ぶ。「あとで」で閉じられる
  - 登録したコースは、別の日・別の車でも、スタートの位置と向きで自動で見分ける(進行方向 ±110m・横 15m・向き 20° 以内。グリッドが後ろでもよい)
- 画面の「車」「セッティング」「コース」に今の状態を出す
- **最近のできごと**: 車両の検出・確定、レースの開始・終了、コースの登録、修正を、記録していないときも新しい順に出す(カードを「あとで」で閉じても、ここに残る)
- **直前のレース**: 最後に見つけたレースのコースと車・セッティングを出す。「コース名・車名を直す」で、レースが終わった後・記録を止めた後でも直せる
  - コースは、登録済みのものを選ぶか新しく登録する。名前を書き換えると、登録しているコースの名前そのものが変わる(次からもその名前で出る)。車名・セッティング名も同じ
  - そのレースが記録中に始まったものなら、直した内容をその記録の `session.json` に `race_edited` として足す(記録を止めた後でも。何も変えずに保存しても、そのときの名前を書く)。再生アプリは直した名前で出す
  - 確認カードで車名・コースを入れた場合は `car_confirmed`・`course_confirmed` として書く(`race_edited` ではない)。再生アプリはどちらでもそのレースの名前として使う
- 記録中の出来事(`car_detected` `car_confirmed` `race_start` `race_end` `course_confirmed`)は `session.json` の `events` に書く(`docs/session-format.md`)

**登録ファイル** `fh6_registry.json`(保存先フォルダの直下)。形式は `docs/session-format.md`。
読めない・壊れているときは記録を止めず、元のファイルに `.broken` を付けて残して新しく作る(画面に警告を出す)。

**再生アプリで付けた名前の取り込み**: 再生アプリの「名前を付ける」で付けたコース名・車名・セッティング名は、保存先の `fh6_registry_inbox.json`(登録の受け渡し用のファイル)に頼みとして届く。
起動したときと、動いている間 3 秒ごとにこれを見て、登録ファイルに取り込んで消す(「最近のできごと」に「再生アプリから …」と出す)。取り込みの決まりは「直前のレース」の直し方と同じで、同じものは二重に登録しない(`docs/session-format.md`「登録の受け渡し用のファイル」)。

## 出力

保存先(既定は「ビデオ\FH6Recorder」。アプリ名を変える前からのフォルダ名で、既存の記録と `.access_key` を引き継ぐため変えていない)にセッションごとのフォルダ `yyyyMMdd_HHmmss` を作る(メモを入れて記録を始めたら `yyyyMMdd_HHmmss#メモ`。後から名前の後ろにコメントを足してもよい)。

| ファイル | 内容 |
|---|---|
| `telemetry.csv.gz` | 1 パケット 1 行の CSV。`recv_time` は epoch 秒、`is_race_on==0` の連続区間は先頭行と末尾行だけ残す |
| `telemetry.raw.gz` | 受信した生パケットを全部。`FH6RAW01` + `ushort 324` の後に `[double recv_time][ushort len][bytes]` の繰り返し。`SaveRawPackets:false` で無効 |
| `session.json` | 記録の情報(`session` / `markers` / `stats` / `video` / `events` / `files`)。記録中も30秒ごとに `complete:false` で途中保存。録画の開始を要求した時刻は `video.start_requested_recv_time` |
| 動画 | OBS 30 以降なら、録画中だけ OBS の録画フォルダをこのフォルダに切り替え(終了後に元へ戻す)。それより古い OBS では OBS の既定フォルダに残り、パスを `video.output_path` に記録 |

### 動画との同期

動画の0秒は、OBS の**録画開始イベントを受けた時刻**とする(`video.video_zero_recv_time`)。テレメトリ時刻 → 動画時刻は `recv_time − video_zero_recv_time`。
実測の根拠は `docs/session-format.md` の「video」の節。

- `video.sync_samples`: 録画中に約2秒ごとに OBS へ「今の時点で動画は何秒か」(`GetRecordStatus.outputDuration`)を問い合わせた記録。
  OBS の報告は実際より約1秒遅れるので時刻の変換には使わず、動画の時間軸の伸び縮みの確認に使う
- `video.clock_rate`: `sync_samples` の傾き。1.0 からずれていれば動画の時間軸が実時間と違う
- `video.file_duration_sec`: 停止後に録画ファイル(MP4)から読んだ実際の長さ。`video.file_fps` に映像のフレームレートも書く(再生アプリのコマ送り用)
- `video.end_check_sec`: (停止要求の時刻 − 動画0秒)と、ファイルの長さの差。
  0 に近ければ動画0秒は正しい。前回の記録の欄にも表示される

2026-09-28 より前の記録は、動画0秒を `sync_samples` から求めていて約1秒遅い。`--resync` で作り直せる。

記録済みのセッションは `HeisoRecorder --resync <セッションフォルダ>` で、動画の長さ・フレームレートと終端の検算を書き足せる
(元の session.json は session.json.bak に残す)。

## 注意

- 生パケット(`telemetry.raw.gz`)も残しているので、列名や読み方を直したときは CSV を後から作り直せる
- FH6 で増えた 12 バイト(offset 232〜243)は `car_group`(int32)、`smashable_vel_diff`(float)、`smashable_mass`(float)として読んでいる
- スマホからつながらないときは、PC 画面の「PCのアドレス」で別の候補を選ぶ(仮想アダプタのアドレスが先に出ることがある)
